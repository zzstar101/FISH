# PC Web T10：发布收口与运行验收

> 状态：设计，待实现。依赖 T3–T9 的主链完成。
> 主跟踪：GitHub #89「B：Web 桌面版前端」。

## 1. 目标

把 PC Web 从“页面可用”收口到“可稳定发布”：

- 全局错误和 404。
- 登录过期、深链、回跳、刷新。
- 生产反代与静态资源。
- 可访问性、键盘操作和桌面视口基线。
- 跨页面缓存一致性。
- #217 ID 边界盘点。

## 2. 路由与错误

新增根级错误边界和 not-found：

- 页面抛错时保留顶栏/侧栏，不整页白屏。
- 不存在的 `/pc/*` 显示 PC 404，不落回移动端页面。
- 错误页提供重试和返回首页。
- `/pc` 规范化到 `/pc/`。

## 3. 登录与深链

回归矩阵：

- 未登录访问首页、搜索、详情、消息、订单。
- 登录后回原路径，包括 query 和 hash。
- 401 后清账号缓存并回登录页。
- 多标签页登出后旧标签的 401 行为一致。
- 浏览器前进/后退不产生重复提交。

## 4. 生产验证

- `bun run build:web-pc`。
- Vite preview 或本地静态服务验证 `/pc/` 与深链。
- Caddy / nginx 按 `docs/deployment.md` 验证：
  - `/pc` 308；
  - `/pc/*` SPA fallback；
  - `/pc/assets/*` 长缓存；
  - `/api` 与 `/ws` 同源。
- CI 必须包含 PC build。

## 5. 体验与可访问性

- 视口基线 1280px，不做移动折叠布局。
- 所有交互可用键盘完成。
- 表单有 label、错误与 `aria-invalid`。
- 图标按钮有 accessible name。
- 颜色对比符合现有设计令牌。
- 图片有 alt；装饰图空 alt。
- 加载、空、错误状态可区分。

## 6. 跨页面一致性

- 发布成功后：首页、搜索、我的发布、详情缓存一致。
- 编辑商品后：详情、列表、个人中心一致。
- 完成交易后：订单、商品、消息一致。
- 登出/换号后：T3 的 `pc` 缓存边界成立。
- 所有账号/业务数据 query key 使用 `pc` 前缀；`auth/me` 是唯一认证控制 key。

## 7. #217 ID 盘点

在 #217 合并前冻结检查表：

- 路由参数是否仍假设 UUID。
- DTO 是否包含可展示编号。
- 搜索框是否混用编号和关键词。
- 复制/分享 URL 是否稳定。
- cursor 是否把 UUID 当公开排序键。

未冻结前不自行新增 TypeID 前缀或编号搜索。

## 8. 验收标准

- [ ] 全仓 typecheck、lint、test 通过。
- [ ] `build:web-pc` 通过并在 CI 运行。
- [ ] `/pc/` 深链与 404 行为正确。
- [ ] 登录过期、换号、多标签页回归通过。
- [ ] 桌面 1280/1440/1920 视口无关键布局断裂。
- [ ] 键盘操作和主要表单无障碍检查通过。
- [ ] 生产反代配置按部署手册实际验证。
- [ ] #217 盘点表完成，无未登记 ID 假设。

## 9. 非目标

- 移动端折叠布局。
- PWA 安装或离线能力。
- 性能微优化没有指标支撑的部分。
- Admin 控制台迁移。
