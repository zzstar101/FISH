# 小程序前端开发强制验证工作流（Mandatory Workflow）

> 适用对象：所有对 `apps/miniapp`（FISH 微信小程序，Taro 4 + React）的**前端改动** —— 无论是人还是 AI agent。
> 这是一条**强制规则**，不是建议。违反即视为流程违规。
> 端上验证优先级：**微信开发者工具 > 真机实机 > 其它一切**。H5/纯代码层面的检查**不能替代**微信开发者工具里的验证。

---

## 0. 为什么必须这样

小程序是**端上运行时**：原生 TabBar、自绘导航、真机字体、safe-area、`navigationStyle: custom` 的布局，
在浏览器 / 命令行里看不出真实效果。只靠看代码、跑 typecheck、或 H5 预览就认为"做好了",会
漏掉大量真实机型上才暴露的问题。因此**每个页面改动，落定前必须回到微信开发者工具里看一遍**。

---

## 1. 每个页面 = 一个新分支

- **一个页面（包含它的样式、组件、交互逻辑）一个独立分支**，分支命名：
  `feat/miniapp-<页面名>-<改动要点>-<序号>`，例如：
  - `feat/miniapp-home-searchcap-fix`
  - `feat/miniapp-detail-similar`
- 分支从**最新 `main`** 切出，保证基线最新。
- **一次分支只做一件事**：不要在一根分支里同时改多个页面，避免 review 与回滚纠缠。

---

## 2. 上一个分支完成，才能开下一个（串行门禁）

- **开新分支前，必须先确认当前分支的工作已经完成**，即：
  1. 该分支的改动已在微信开发者工具里**验证通过**；
  2. 已按规则提交（见第 4 节）；
  3. 该分支已换算/合入到基干（`main` / 上一级分支），或至少已**推送且被（Owner）确认**。
- **不允许叠着开分支**：在上一个分支还没 "完成 + 提交 + 合入/确认" 之前，**不得**再开下一个页面的分支。
- 判断"上一个分支是否完成"的方法：`git status` 干净、当前已切回 `main`、且 `git log main..<上一分支>` 为空（已被合入）或该分支已确认归档。
- 若上一个分支还有未完成项，**先停下，提醒 Owner 处理它**，而不是带着它开新分支。

---

## 3. 动手修改前，必须先提醒 Owner

- 在对任何页面代码（`apps/miniapp/src/**`）**动手修改之前**，**必须先把「要改哪个页面、改什么、预期效果」明确告知 Owner（人类）**，得到确认后再动手。
- 提醒的方式：直接在对话里说明计划，并明确请 Owner 确认。**不要未经提醒就直接改代码。**
- 这条同样约束 AI agent：agent 在编辑任何 `apps/miniapp` 页面/组件/样式前，必须先向 Owner 说明并等待确认。

---

## 4. 通过演示验证，才允许提交

提交（commit/push）必须满足**全部**：

1. **微信开发者工具里演示通过**：改动后在工具里实际打开该页面，
   - 真机渲染正常（无白屏、无排版错乱）；
   - 交互（点击、输入、跳转、弹层、loading/error 态）符合预期；
   - 与设计稿/上一版相比没有引入明显视觉回归。
2. **Owner 确认效果可行**：把演示结果（截图 / 描述 / 现象）给 Owner，Owner 认可后再提交。
   - **"演示通过 + Owner 认可" 是提交的必要前置条件**，两者缺一不可。
3. **静态检查通过**：`bun run --filter '@fish/miniapp' typecheck` 与 `bun run lint` 无错误。
4. 提交信息用 Conventional Commits，遵守 `CONTRIBUTING.md`。

> 顺序：改前提醒 → 改代码 → 微信开发者工具演示 → Owner 确认可行 →（typecheck/lint 通过）→ 提交。

---

## 5. 兜底与特例

- **纯文档 / 纯配置 / 纯类型**变更（不涉及任何渲染或交互），可豁免微信开发者工具演示，
  但仍须遵守"每个页面一个新分支、上一个完成再开下一个、改前提醒、提交前 Owner 确认"的串行门禁与提醒规则。
- **不确定是否算"页面改动"时，按"算"处理** —— 宁可多验证，不可漏验证。
- 微信开发者工具不可用时（本地没装 / 未登录），**视为阻塞**：如实告知 Owner 无法端上验证，
  **不擅自以 H5 或纯代码检查充当端上验证**，也不绕过门禁提交。

---

## 6. 一句话总结

**一个小程序页面改动 = 一条新分支；上一个完成才开下一个；动手前先问 Owner；微信开发者工具里演示、Owner 确认可行后才提交。**
